قبل از شروع مدل‌سازی

هدف، نقش، نقطه شروع، ساختار پروژه و آماده‌سازی — چهارچوبی که هر تصمیم در مسیر تولید را هدایت می‌کند.

۱

هدف این workflow

هدف این نیست که به Hermes بگویی: «چغازنبیل رو بساز.»

هدف این است که یک asset پیچیده را به چند تصمیم کوچک، قابل‌اندازه‌گیری و قابل‌بررسی تقسیم کنی.

چرخه‌ی اصلی همیشه این است: Brief → Plan → Approve → Implement → Execute → Preview → Review → Accept

و قانون اصلی:

هر Task فقط یک تغییر بصری قابل‌بررسی دارد.
۲

نقش تو چیست؟

تو قرار نیست Blender Artist حرفه‌ای باشی. نقش تو بیشتر شبیه این‌هاست:

Director + Art Director + Technical Director

تو باید بتوانی بگویی:

  • چیزی که می‌خواهم چیست؟
  • چه چیزی در خروجی غلط است؟
  • چه چیزی هنوز نباید ساخته شود؟
  • آیا نسبت‌ها درست‌اند؟
  • آیا silhouette درست است؟
  • آیا دوربین چیزی را که می‌خواهم منتقل می‌کند؟
  • آیا جزئیات تاریخی واقعاً پشتوانه دارند؟

لازم نیست بدانی برای درست‌کردن آن دقیقاً کدام bpy API باید استفاده شود. این وظیفه‌ی agent است.

۳

برای چغازنبیل از کجا شروع کنیم؟

از کل چغازنبیل شروع نکن. از شهر دوراونتاش هم شروع نکن. از landscape، درخت، مردم، لباس، آسمان و material هم شروع نکن.

اول فقط این سؤال را جواب بده:

آیا می‌توانیم جرم اصلی و نسبت‌های زیگورات چغازنبیل را به شکل تاریخی قابل‌دفاع و بصری قابل‌قبول بسازیم؟

پس اولین milestone: Chogha Zanbil — Ziggurat Reconstruction

و اولین Task: Primary Blockout

۱۰

در Planning Session دنبال چی بگردم؟

تو لازم نیست کد را بررسی کنی. این‌ها را بررسی کن:

🔍
آیا scope کوچیک مانده؟

اگر نوشته «سپس material خشتی و erosion هم اضافه می‌کنیم...» ردش کن. بگو: «Remove material and erosion work from this task. Keep the task strictly limited to primary blockout geometry.»

📐
آیا construction strategy منطقی است؟

برای یک زیگورات dimensioned احتمالاً primitives + deterministic dimensions + repeated structures + modular objects + Blender Python.

⚠️
آیا Unknownها را پنهان نکرده؟

اگر ارتفاعی نامشخص است باید بگوید Unknown، نه اینکه خودش عدد بسازد.

۱۱

چه زمانی Plan را Lock کنم؟

وقتی این موارد مشخص‌اند:

  • هدف
  • strategy
  • inputها
  • outputها
  • acceptance criteria
  • do-not-change
  • unknownها

آن موقع بهش بگو:

Plan approved. Treat this plan as locked for implementation. Do not redesign the geometry strategy unless implementation proves the plan impossible or contradictory.

این Scope Lock است. از این لحظه DeepSeek اجازه ندارد وسط کار architectural design جدید اختراع کند.

۱۲

حالا Session را عوض کن

اینجا مهمه: Sol session را ادامه نده. یک session جدید با مدل DeepSeek V4 Flash بساز.

چرا؟ چون DeepSeek فقط باید این‌ها را ببیند:

  • approved task plan
  • task contract
  • reference pack
  • project profile
  • start workfile

لازم نیست کل بحث و کل exploration سول را بخواند.

فصل ۳ قفل، بررسی و بازخورد

چطور مطمئن شویم مسیر درست می‌رویم

سه نوع Lock، روش Review، Feedback مؤثر، Correction Strategy و پایان Task.

۱۴

سه نوع Lock

۱. Scope Lock

بعد از approve شدن Plan. یعنی: دیگر strategy را بدون دلیل عوض نکن.

۲. Workfile Lock

وقتی agent قرار است یک authoritative WIP را تغییر دهد. در Production: acquire lock → mutate WIP → save new version → finish execution → release lock. اگر یک agent روی SRZ_CZ_Ziggurat_Primary_v004.blend کار می‌کند، هیچ agent دیگری همزمان writer همان workfile نباشد.

۳. Approval Lock

وقتی phase قبول شد. این snapshot دیگر نباید تغییر کند. مرحله بعد از آن fork می‌شود.

۱۵

اولین خروجی چه شکلی باید باشد؟

احتمالاً زشت. و این کاملاً درست است.

انتظار این چیزها را نداشته باش: نور سینمایی، بافت خشتی جذاب، erosion، خاک، درخت، آدم، آسمان، مه، جزئیات معماری، dramatic composition.

باید چیزی شبیه یک مدل خاکستری تمیز ببینی. اما وقتی آن را از دور نگاه می‌کنی باید بگویی: «آره، فرم و scale چغازنبیل داره درمیاد.» این موفقیت Phase 1 است.

۱۶

چطور Review کنم؟

  1. Silhouette — اگر silhouette غلط است: هیچ چیز دیگری مهم نیست.
  2. Overall Proportions — عرض، ارتفاع، levelها.
  3. Major Negative Spaces — فضاها، مسیرها، بازشوهای اصلی.
  4. Rhythm — تکرارها، پله‌ها، دیوارها.
  5. Detail — آخر کار.
۱۷

Feedback بد و خوب

این بد است:

«خیلی عجیب شده. یه چیزیش بده. درستش کن.»

Agent نمی‌داند چه کاری بکند.

این بهتر است:

The overall silhouette is close. The upper mass appears too narrow relative to the lower body. Keep the footprint and lower levels unchanged. Review only the width progression of the upper levels against the approved references. Do not change stairs or orientation.

این feedback bounded است.

۱۸

Correction Strategy

Correction را در همان Session انجام بده. اگر همان مشکل است: Blockout → correction 1 → correction 2 در همان DeepSeek session بمان. اما بیشتر از دو correction برای یک mismatch ساختاری انجام نده.

اگر DeepSeek دو بار خراب کرد؟ بار سوم بهش نگو «دوباره امتحان کن.» Stop. مشکل را classify کن: implementation problem؟ planning problem؟ missing reference؟ contradictory evidence؟ runtime bug؟

اگر strategy مشکل داشت: برگرد Sol/Astra با session تازه:

The implementation failed twice to produce the required
stepped proportion.

Do not implement.

Analyze the approved plan and the two review failures.

Determine whether the geometry strategy is wrong.

Return only a revised implementation strategy.

بعد plan جدید را approve کن. بعد دوباره DeepSeek session تازه.

۱۹

کی Task تمام شده؟

وقتی acceptance criteria همین Task پاس شده. نه وقتی مدل کامل شده.

مثلاً اگر Blockout درست شد: CZ-ZIG-001 تمام است. حتی اگر مدل هنوز زشت است. این دقیقاً چیزیه که باید یاد بگیری.

۲۰

بعد از قبول Task چه کنم؟

Prototype: ذخیره کن SRZ_CZ_Ziggurat_Blockout_v003.blend و review notes. بعد source/script/task files را checkpoint یا commit کن.

Production: WIP → REVIEW → validate from REVIEW → APPROVED. بعد commit.

۲۱

Commit کی بزنم؟

بعد از Accepted Task Boundary. نه بعد از هر prompt. نه بعد از هر render. نه بعد از هر script run.

مثلاً: feat(cz): approve ziggurat blockout. بعد phase جدید شروع شود.

۲۲

Session جدید کی بسازم؟

همان Session بمان اگر: همان Task است، همان phase است، فقط feedback می‌دهی، correction اول یا دوم است، objective تغییر نکرده.

Session جدید بساز اگر: phase تمام شد، task جدید شروع شد، از Sol به DeepSeek رفتی، از Blender به Unreal رفتی، objective تغییر کرد، agent اشتباه قبلی را دوباره تکرار کرد، context پر از راه‌های ردشده شده، حس کردی مدل دیگر task را تمیز نمی‌فهمد.

قاعده‌ی ساده: هر Accepted Phase = یک Session Boundary خوب.

کل مراحل Asset چغازنبیل

  7. Phase 7 — Approved Asset: Asset تاریخی آماده‌ی استفاده در scene است

۲۹

Planner: Sol یا Astra؟

Sol — default خوب برای: task decomposition، architecture strategy، ambiguous reconstruction، camera planning، pipeline decisions، debugging strategy، deciding Blender vs Unreal

Astra — اگر تجربه‌ات نشان داد در این‌ها بهتر است: geometry-heavy problem، spatial relationships، difficult reference fitting، complex architectural reasoning

۳۰

DeepSeek را برای چه چیزی نگه دارم؟

برای execution: bpy scripts، primitive construction, transforms, arrays، repeated architecture, collection management, deterministic placement, export preparation, camera setup, simple procedural generation, fixes با strategy مشخص

DeepSeek نباید دوباره تبدیل به Architect پروژه شود.

۳۱

چه زمانی Sol را برای Implementation استفاده کنم؟

فقط وقتی implementation خودش سخت شده: procedural geometry پیچیده، topology-sensitive work، boolean interaction سخت، mathematical mesh generation، script architecture پیچیده، DeepSeek دوبار strategy درست را اشتباه اجرا کرده. نه صرفاً چون asset بزرگ است.

فصل ۵ مهارت و تمرین

نوشتن Prompt مؤثر و شروع کار واقعی

صرفه‌جویی در Token، ساختار Prompt، مفاهیم Blender، و روز اول و دوم پروژه.

۳۲

صرفه‌جویی در Token

  • هر Session فقط منابع لازم را بده — برای Task پله لازم نیست reference لباس و landscape load شود
  • Planning Conversation را به Implementation نفرست — فقط task-plan.md + task contract + ref pack + current workfile + project profile
  • خروجی agent را محدود کن — فقط: Changes Made, Intentionally Unchanged, Outputs, Validation, Remaining Mismatch, Blockers, Recommended Next Task
  • یک مشکل را ده بار توضیح نده — اگر review artifact داری از همان استفاده کن
  • Session مرده را نکش — اگر agent دو بار اشتباه قبلی را تکرار کرد: session جدید. Context بیشتر همیشه intelligence بیشتر نیست. گاهی دقیقاً برعکسه.
۳۳

Prompt Anatomy

تقریباً هر prompt اجرایی تو باید این هفت چیز را داشته باشد:

1. Skill
2. Task
3. Goal
4. Inputs
5. Scope
6. Do Not Change
7. Output

مثال:

Use blender-modeling.

Task:
CZ-ZIG-003 — Main Stair Structural Detail.

Goal:
Build the approved main stair geometry.

Inputs:
Use the approved Primary Forms workfile and stair
measurement reference pack.

Scope:
Only modify the main stair subsystem.

Do Not Change:
Do not modify ziggurat massing, orientation, terrace
dimensions, materials, camera, or environment.

Output:
Create a new versioned workfile and produce one side view,
one top view, and one 3/4 clay review.

Stop if the measurements conflict.
Do not infer missing historical dimensions silently.
۳۴

Promptهایی که نباید استفاده کنی

«مدل رو بهتر کن» — بد است.
«جزئیات بیشتری بده» — بد است.
«مثل رفرنسش کن» — بد است.
«خیلی طبیعی‌تر و تاریخی‌ترش کن» — بد است.

چون agent باید حدس بزند مشکل چیست.

۳۵

به‌جای آن بگو

The primary mass is accepted. The stair width and terrace spacing still differ from the approved reference. Modify only those two relationships. Keep the ziggurat footprint, total height, orientation, and upper mass unchanged.

این زبان باید تبدیل شود به زبان عادی تو برای کار با agent.

۳۶

مفاهیم Blender که باید بدانی

Geometry: mesh، vertex/edge/face، transform، origin، scale، dimensions، topology

Modeling: extrude، inset، bevel، boolean، array، mirror، modifier، curve، Geometry Nodes

Scene: object، collection، hierarchy، linked object، instance

Camera: focal length، sensor، perspective، depth of field، clipping

Materials: material، shader، texture، UV، roughness، normal

Animation: frame، keyframe، interpolation، timeline

۳۷

مهم‌ترین مهارت

تشخیص اینکه چه چیزی غلط است.

نه: «حسش خوب نیست.» بلکه: «دوربین زیادی بالاست و حس حضور انسان کنار بنا از بین رفته.» یا: «نسبت طبقات باعث شده بنا باریک‌تر از reference دیده شود.» یا: «جزئیات قبل از اینکه جرم اصلی درست شود، زیادی برجسته شده‌اند.»

این توانایی برای workflow تو از سرعت manual modeling مهم‌تر است.

۳۸

روز اول واقعی چغازنبیل
